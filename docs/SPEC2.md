# Appbuilder phase 2: build spec

Read first: `src/contracts.ts`, `src/platform/contracts.ts`, `src/router.ts`, `docs/SPEC.md` (phase 1, still valid where not overridden here).

Product: a **desktop** low-code app builder with a modern look. Apps are landscape only, designed at Full HD (1920×1080) or 2K (2560×1440) and adapt to any landscape aspect ratio. No portrait, no phone layouts. Flows are out of scope. Own identity ("Appbuilder", indigo); layout patterns may follow familiar maker-portal conventions but no Microsoft names, assets or colours.

All dependencies are already installed (do NOT run `npm install`, it races with other agents): radix primitives (slot, tabs, select, checkbox, dropdown-menu, tooltip, scroll-area, dialog, switch, popover, radio-group, slider, accordion, avatar, progress, toggle-group, toggle, collapsible, alert-dialog, context-menu, hover-card), cmdk, react-day-picker, date-fns, recharts, js-yaml, papaparse, lucide-react, zustand, immer, cva, clsx, tailwind-merge. Do not run git.

## 4. Desktop sizing and responsive layout (Studio agent; controls just expose props)
- New-app dialog and app settings: design resolution preset Full HD 1920×1080 (default) or 2K 2560×1440, custom allowed only when width ≥ height; `scaleMode` responsive (default) or fit.
- **Responsive rule**: at run time the Screen's actual size = window size (min 1024×576, landscape enforced: if the window is taller than wide, keep the design aspect and letterbox). Each child of a **Manual** parent is placed from its evaluated design rect (X, Y, Width, Height at the parent's design size) and its anchors against the parent's ACTUAL size: `Anchor.Start` keep distance to left/top, size fixed · `End` keep distance to right/bottom · `Stretch` keep both distances (size grows) · `Center` keep offset from centre · `Scale` position and size scale proportionally. A parent's design size is its own evaluated Width/Height; the Screen's is `app.width × app.height`. Children of **Row/Column/Grid** parents are flow items: Width/Height are the flex-basis in the main axis and the size in the cross axis unless `AlignSelf`/`AlignItems` is Stretch; `Grow` > 0 fills remaining space; X/Y are ignored.
- Formulas can read `App.Width`, `App.Height`, `App.DesignWidth`, `App.DesignHeight`, `Parent.Width`, `Parent.Height` (actual sizes), `Self.*`.
- Studio canvas: viewport selector in the status bar: Design size (editable) · 1920×1080 · 2560×1440 · 1366×768 · 1920×1200 (16:10) · 2560×1080 (21:9) · 3440×1440 · custom. Geometry editing (move/resize/insert) only at the design size; other viewports are a live read-only preview with a banner "Viewing at W×H. Switch to design size to edit" (selection still works so anchors can be changed in the panel). Canvas default zoom = fit. Rulers optional. Insert defaults and snapping grid tuned for 1920×1080 (8px grid).
- In auto-layout parents, dragging a child reorders it among siblings (insertion indicator); resizing changes Width/Height basis.
- Migration: phase-1 apps (960×600, formatVersion 1) load as scaleMode 'fit'.

## 5. Data: tables as local CSV (Platform agent)
Implement `platform: PlatformApi` exported from `src/platform/index.ts`, plus React hook `usePlatform<T>(selector: (s: WorkspaceState) => T): T` (useSyncExternalStore).
- `server/`: a dependency-free Node server (`server/index.mjs`, ESM) exposing `GET /api/fs/health`, `GET /api/fs/read?path=`, `PUT /api/fs/write?path=` (text body), `DELETE /api/fs/remove?path=`, `GET /api/fs/list?dir=` against `./workspace` (override with `APPBUILDER_WORKSPACE`), rejecting any path that escapes the root (`..`, absolute, backslashes), atomic writes (temp file + rename), creating folders as needed; it also serves `dist/` statically so `npm start` runs the built app. The same handler is mounted as Vite dev middleware (small plugin in `vite.config.ts`) so `npm run dev` has the API. Add `"start": "node server/index.mjs"` to package.json scripts (only that line).
- Storage adapters: `LocalFolderStorage` (fetch to `/api/fs/*`) chosen when `/api/fs/health` answers within 800 ms on http(s) origins; else `BrowserStorage` (IndexedDB, with in-memory fallback if IndexedDB throws). Never throw to the UI because storage is missing.
- CSV with papaparse: header row = column names, RFC 4180 quoting, dates ISO-8601, booleans `true`/`false`, blank = empty. Typed coercion both ways. Debounced (300 ms), serialised writes per table; `flush()`.
- Every table has system columns `id` (uuid text), `createdOn`, `modifiedOn` (datetime), `createdBy`, `owner` (user id). `__id` mirrors `id` on rows returned to callers.
- Validation on insert/update: required, unique, type coercion failures, choice membership, lookup target existence; autonumber assignment. Renaming a table is not supported (displayName only); column rename is displayName only; removing a column drops it from the CSV.
- Security: evaluate the current user's roles (union, broadest wins): read scope filters `rows()`; create/update/delete checked per row (`own` = `owner` equals current user). Admin role bypasses. This is a single-machine simulation of role security; say so in code comments, do not pretend it is a server boundary.
- Seed on first run: users Admin (admin role) and "Sam Maker" (Maker role: all on all tables) and "Vera Viewer" (Viewer role: read all, no writes); tables `Contacts` (Name, Company, City, Email, Active boolean, Status choice) with 8 rows and `Orders` (OrderNo autonumber, Customer lookup→Contacts, Amount currency, OrderDate date, Status choice) with 12 rows; one connection `Local CSV` (connected); one solution "Default" containing everything; one app "Contacts app" from the sample (ask the runtime's `sampleApp()` if exported, else create blank at 1920×1080).
- Packages (YAML via js-yaml, `kind: appbuilder/app` or `appbuilder/solution`, `packageVersion: 1`): see contract. Import assigns new ids, makes names unique ("Contacts app (2)"), rewrites nothing inside formulas (table names are reused/created by name).
- Tests (vitest, node env, with an in-memory StorageAdapter injected): CSV round-trip incl. quotes/newlines/dates, validation, security scopes, autonumber, lookup validation, app package export→import creates a new instance, solution export→import, path-escape rejection in the server handler. ≥60 assertions.
